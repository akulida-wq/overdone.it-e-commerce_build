# BIG_DESKTOP — как масштабируется overdone.it (исследование R3-P1, 2026-08-29)

Замеры живого https://overdone.it/ через puppeteer + системный Chrome (computed styles),
ширины 1440–2560 с шагом, скриншоты в скретчпаде сессии.

## 1. Контейнер

- Обёртка `.wrapper`: **без фиксированного max-width** — ширина ≈95vw, растёт флюидно
  и упирается в кап **1790px** (достигается на ~1884px вьюпорта).
- 1440 → контент 1368px; 1600 → 1520; 1800 → 1710; 1920–2559 → 1790 (кап, по центру).
- На ≥2560 кап вырастает до **2387px** (= 1790 × 4/3).

## 2. Типографика

- **1440 и 1920 идентичны**: hero 140 / h2 56 / карточки 40 / лиды и кнопки 20.
  Между 1441 и 2559 нет ни одного изменения размера шрифта — только контейнер шире.
- Единственный вертикальный брейкпоинт вверх: **`@media (min-width: 2560px)`**
  (проверено бинарно: 2559 → 56px, 2560 → 78px у h2).
- Скачок на 2560 (рукописные значения, не один множитель):
  | элемент | 1440–2559 | ≥2560 | множитель |
  |---|---|---|---|
  | hero display | 140px | 240px | ×1.71 |
  | h2 | 56px | 78px | ×1.39 |
  | карточки/h3 | 40px | 56px | ×1.4 |
  | подзаголовки | 40px | 48px | ×1.2 |
  | лиды/кнопки | 20px | 27px | ×1.35 |
- `html { font-size }` всегда 16px — скейл не через rem и НЕ через zoom
  (zoom-цепочка пустая, computed проверен).
- letter-spacing задан в px и на 2560 не пересчитан (−1.68px при 78px ≈ −2.2%).
  У нас оставляем em — вернее по духу.

## 3. Вертикальный ритм

- Паддинги секций 64px сверху/снизу на всех ширинах; на 2560 контактная секция
  растёт 64→80 (×1.25). То есть ритм почти не масштабируется — воздух добавляет
  сам контент.

## 4. Кнопки `.button` (эталон для PButton)

- Геометрия: flex, height **48px**, radius 52px (pill), padding **0 14px**,
  зазор между элементами 12px, текст в `<span>` **20px**, letter-spacing normal,
  вес 400. Транзишен **0.4s** на всём.
- Состав: `svg.button__svg_left` (стрелка →, 24×24, stroke currentColor 1px) +
  `<span>` + `svg.button__svg_right` (стрелка ↗ внутри повёрнутой скруглённой
  квадратной рамки, 24×24, currentColor; в покое width 0 / opacity 0).
- **Hover**: левая стрелка схлопывается (width 24→0, fade 1→0), текст съезжает
  к левому паддингу, справа разворачивается правая иконка (width 0→24, fade 0→1).
  Ширина кнопки НЕ меняется. Фон/цвет текста не меняются ни у одного варианта.
- **Active**: ничего дополнительного (нет scale/цвета).
- Варианты: `.button` красный #F12625/белый текст; `.gray` rgba(255,255,255,0.1);
  `.white` белый фон/чёрный текст.
- ≥2560: height 64, padding 0 24px, span 27px, иконки ~32px.

## 5. Как это перенесено к нам

- Размерные токены переведены на CSS custom properties (`_scale.scss`):
  база 1440 + переопределения `@media (min-width: 2560px)`. SCSS-имена
  (`$fs-h2`…) сохранены и указывают на var() — компоненты не меняются.
- Контейнер: `--container-max: 1720px` (флюидный рост 1440→1848 как у основного
  сайта, наш кап = 1312 × 1790/1368) → `2290px` на ≥2560.
- Типошкала ≥2560: hero 128→220, h2 56→78, h3 40→56, h4 32→44, body-lg 20→27,
  body 16→21, small 14→18, nav 15→20, mono 14→18 (те же множители, что у
  основного сайта).
- Ритм: `--rhythm-half` 64→88 (по контактной секции основного сайта ×1.25 с запасом).
- Кнопки: `--btn-h/--btn-pad/--btn-fs/--btn-icon/--btn-gap` 48/14/20/24/12 →
  64/24/27/32/16.
- Структурные ширины секций (фиксированные колонки из макета 1440) масштабируются
  множителем `--k`: 1 → 1.4 на ≥2560.
- 1920 отдельных токенов не требует (как и у основного сайта): работает флюидный
  контейнер + vw-размеры hero-ассетов.
